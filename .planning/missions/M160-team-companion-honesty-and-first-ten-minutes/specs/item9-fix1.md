# M160 item 9 — fix round 1 (from the fresh Opus verifier, .planning/missions/M160/VERIFY-R1.md)
CI fails deterministically: e2e/tests/tree-meta.spec.ts:17 — after "Create tree", `getByTestId('tree-title')` is never found (the Suspense around the title in src/pages/tree_drafter.rs ~:629 stays on its `fallback=|| ()`), then a 60 s timeout.
Cause named by the verifier: `dossier_list` (~:399) is a `Memo` wrapping the `dossiers` Resource, and it is read inside Suspense closures (~:563 tree list, ~:603 new-tree select, ~:634 title opponent label, ~:665 edit-form select) that otherwise wait only on `trees`. A resource read through a Memo created outside the Suspense is not registered with that Suspense the way a direct read is, so SSR and the browser disagree (hydration) and the title Suspense never resolves.
Fix (keep the feature and its behaviour; change only how the dossiers are read):
1. Delete the `dossier_list` Memo. Inside EVERY closure that needs the dossiers, read the resource directly: `let dossiers = dossiers.get().and_then(|r| r.ok()).unwrap_or_default();` (Resource is Copy, so each closure can capture it).
2. Split the title: the tree title `<span data-testid="tree-title">` stays in a Suspense that reads ONLY the trees resource (via `tree_title()`); the "vs {label}" opponent span goes into its OWN `<Suspense fallback=|| ()>` next to it that reads `dossiers` directly and `tree_title()`. So the title never waits on the dossiers.
3. Same for the tree list (~:563): the list must render from `trees` even if dossiers are still loading; read dossiers directly inside the per-row closure for the label (falling back to the raw text label only for legacy free text; for an `opponent:` id with dossiers not loaded yet, render no label rather than the raw id).
4. The two opponent `<Select>`s (~:603, ~:665): read `dossiers.get()` directly inside their Suspense closures.
5. Keep every data-testid / id the e2e uses: tree-title, tree-opponent-label, tree-list, tree-edit-open, tree-edit-form, tree-edit-save, #tree-name, #tree-opponent, #tree-edit-name, #tree-edit-opponent.
6. cargo fmt; memory permitting (pi-common.md): cargo check --features ssr and --features hydrate --target wasm32-unknown-unknown; cargo test --features ssr --lib tree. Change nothing else.
