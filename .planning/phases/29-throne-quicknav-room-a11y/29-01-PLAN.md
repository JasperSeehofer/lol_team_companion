<objective>
Add the Throne growth data layer: `ThroneGrowthCounts` + `ThroneGrowthState` to `src/models/growth.rs` and `get_throne_growth_counts` to `src/server/db.rs`. Unlike `TeamGrowthState`/`LibraryGrowthState`, `ThroneGrowthState` is BLENDED — it has no single `counts` field. Its constructor `from_parts` takes both the team-scoped counts AND the viewing user's optional `RankedInfo`, deriving the `progression` axis independently from the user's ranked games so it advances with no team (D-05/D-07). This is the pure data foundation the Throne room (Plan 05) consumes via `get_throne_growth_state`.

Purpose: SC1 ("the room's environment reflects roster size, LP milestones, and combined team record") and SC1b ("a teamless ranked user still sees progression grow") are driven entirely by these tier values surfacing as `data-roster-tier`/`data-progression-tier`/`data-crown-tier`. The blended derivation is pure and unit-tested here so the D-07 divergence (progression-without-team) is pinned before the UI lands.

Output: two new structs + `from_parts` + `Default` + five `throne_*` unit tests in `growth.rs`; one new 2-statement batch-count fn in `db.rs`. Both compile targets pass; `cargo test --features ssr --lib -- throne` is green.
</objective>
