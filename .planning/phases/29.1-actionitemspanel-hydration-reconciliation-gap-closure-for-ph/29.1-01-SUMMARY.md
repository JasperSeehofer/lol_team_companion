## Decisions Made
- **The plan's diagnosis was incomplete.** It attributed the panic to ActionItemsPanel's own `items`/`members` resources read via `.get().map` inside `<Suspense>`, and prescribed converting 8 blocks to `Suspend::new`. That conversion compiled and ran but the panic persisted at the panel's root `<div>` (`action_items.rs:225/231`). Empirical probing of the live console showed the real failure: `ActionItemsPanel` is a resource-backed sub-component mounted inside the `Ok(Some(_))` branch of `DevelopmentSurface`'s outer `dash`-resource `<Suspense>`. On SSR the outer branch resolves and the panel's inner `<Suspense>` renders RESOLVED content; on hydrate the outer branch starts pending → the panel is not yet mounted → when it mounts, its inner Suspense renders the fallback → SSR-resolved-vs-WASM-pending structural mismatch → reconciler panic. **The nesting, not the read shape, is the defect.**
- **Fix: unconditional mount.** `ActionItemsPanel` and `TeamNotebookInner` already return `Ok(Vec::new())` for no-team users (rule #44), so they can mount unconditionally. The no-team CTA became a reactive `hidden`-toggled banner above the always-present panel, removing the conditional branch entirely so SSR and hydrate render the same structure.
- **Single Suspense supersedes the 8-block design.** Collapsing the panel/page to one Suspense (await both resources once, render synchronously) is cleaner and removes all nested boundaries. This makes the plan's `grep -c "Suspend::new(async move" == 8` acceptance criterion obsolete (now 2). The binding `must_haves.truths` (no panic, interactive, SC4 intact) and `artifacts.contains: "Suspend::new"` + "no `.get().map`" are all satisfied.
