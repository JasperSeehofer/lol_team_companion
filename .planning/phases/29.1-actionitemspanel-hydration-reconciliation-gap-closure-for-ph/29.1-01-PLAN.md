<objective>
Eliminate the `tachys` `Option::unwrap() on None` hydration panic (`hydration.rs:216`, `PAGEERROR: unreachable`) that fires for team users visiting `/throne?tab=development` (and the `/action-items` redirect). The panic is caused by `ActionItemsPanel`'s own `items`/`members` resources being read via the `{move || resource.get().map(...)}`-inside-`<Suspense>` pattern while the panel is mounted inside `DevelopmentSurface`'s conditional `Ok(Some(_))` branch of an OUTER Suspense-wrapped resource. In Leptos 0.8, nested resources read with `.get()` inside a conditional branch of an outer Suspense boundary do not serialize correctly for hydration: SSR resolves the inner resource and renders content, WASM hydration starts with the inner resource pending and renders the skeleton fallback, the DOM structures diverge, and the reconciler panics — killing every WASM event handler in the room.

Purpose: Close the documented Phase 29 regression (known issue in 29-07-SUMMARY.md) so the Throne Development surface hydrates cleanly and its Action Items remain fully interactive for team users. Restores ROOM-06 (Throne hosts team dashboard/development) and A11Y-02 (every room passes hydration-no-panic in both regions) to a genuinely-green state for team users, not just no-team users.

Output: `action_items.rs` refactored so every resource read participates in its Suspense boundary via `Suspend::new(async move { resource.await })` (mirroring the working `opponents.rs`/`analytics.rs`/`profile.rs` pattern); a team-user no-panic + interactivity e2e spec covering both regions; the audit workaround reverted to a real assertion.
</objective>
